# EIDOS v1 — Пилотный Runbook (14 дней на реальном каталоге магазина)

Настоящий документ описывает пошаговый регламент запуска **первого боевого self-hosted пилота EIDOS** на каталоге интернет-магазина (WooCommerce, 1С-Битрикс или CSV/YML) за 1 рабочий день.

---

## 1. Архитектура и ключи безопасности (Self-Hosted)

EIDOS разворачивается на вашем сервере (VPS / Docker, от 2 vCPU / 4 GB RAM, без GPU и без внешних вызовов OpenAI) и использует два раздельных ключа:

| Ключ | Назначение | Права | Где используется |
|------|------------|-------|------------------|
| `ADMIN_KEY` (`EIDOS_API_KEY`) | Серверный административный ключ | Полный доступ: `/v1/catalog/upsert`, `/v1/admin/*`, `/v1/snapshots` | Бэкенд CMS (WooCommerce / 1С-Битрикс), скрипт синхронизации прайса, вход в `/admin` |
| `SEARCH_KEY` | Публичный ключ витрины | Только чтение: `/v1/search`, `/v1/recommend`, `/v1/events` (`403 Forbidden` на запись и `/v1/admin/*`) | Поисковый виджет витрины или фронтенд магазина |

### Быстрый старт контейнера (Docker + Snapshot)
```bash
docker run -d --name eidos-search \
  -p 8080:8080 \
  -v $(pwd)/data:/data \
  -e NODE_ENV=production \
  -e EIDOS_API_KEY="eidos_admin_secret_replace_me" \
  -e EIDOS_SNAPSHOT_PATH="/data/eidos-snapshot.json" \
  -e EIDOS_SNAPSHOT_INTERVAL_MS="300000" \
  eidos-api:latest
```
*(Либо через автоматический скрипт `bash scripts/install-pilot.sh` за Reverse Proxy Nginx/Caddy с HTTPS).*

## 2. Короткие пути подключения каталога (Woo / Bitrix / CSV)

### Путь A — WooCommerce (`integrations/woocommerce`)
1. Соберите архив плагина: `cd integrations/woocommerce && zip -r eidos-woocommerce.zip eidos-search/` и загрузите его в **Плагины → Добавить новый → Загрузить плагин**.
2. В разделе **WooCommerce → EIDOS Search** укажите:
   - `Endpoint URL`: `https://search.yourstore.ru`
   - `Admin API Key`: ваш `ADMIN_KEY`
   - `Search API Key`: ваш `SEARCH_KEY`
3. Нажмите **«Проверить связь (Health)»** → убедитесь в ответе `ready: true`.
4. Нажмите **«Синхронизировать каталог»** → товары выгрузятся батчами (`id = String(post->ID)`, `sku = _sku`).
5. При любой сетевой ошибке или остановке API плагин автоматически возвращает выдачу штатного `WP_Query`.

### Путь B — 1С-Битрикс (`packages/connectors/bitrix` / `integrations/bitrix/eidos.search`)
1. Скопируйте модуль в `/bitrix/modules/eidos.search/` и установите его в **Marketplace → Установленные решения**.
2. В настройках модуля укажите `URL сервера EIDOS`, `ADMIN_KEY`, `SEARCH_KEY` и выберите инфоблок каталога (`IBLOCK_ID`).
3. Нажмите **«Выгрузить каталог сейчас»** (передаются `id = ELEMENT_ID`, `sku = XML_ID / PROPERTY_CML2_ARTICLE`, название, категория, цена и остаток).
4. Включите перехват стандартного компонента `bitrix:search.page`: при недоступности EIDOS (таймаут 1.5 сек) модуль бесшовно переключается на `CSearch` / `CIBlockElement::GetList`.

### Путь C — CSV / JSON / YML (`POST /v1/catalog/upsert`)
1. Подготовьте массив товаров с полями `id`, `title`, `description`, `category`, `price`, `inStock`, `tags`.
2. Загрузите каталог батчами по 250–1000 SKU:
   ```bash
   curl -X POST https://search.yourstore.ru/v1/catalog/upsert \
     -H "Content-Type: application/json" \
     -H "x-api-key: $ADMIN_KEY" \
     -d @catalog-batch.json
   ```
3. Зафиксируйте снапшот индекса на диск:
   ```bash
   curl -X POST https://search.yourstore.ru/v1/snapshots \
     -H "x-api-key: $ADMIN_KEY" -d '{}'
   ```

## 3. Чеклист запуска пилота (4 обязательных шага)

Перед включением трафика покупателей пройдите 4 проверки по порядку:

- [ ] **Шаг 1 (`ready`)**: `curl -s https://search.yourstore.ru/v1/ready` возвращает HTTP `200` и `"ready": true`.
- [ ] **Шаг 2 (`upsert`)**: каталог загружен, `GET /v1/catalog/stats` показывает реальное число товаров (`itemsIndexed ≥ 1000`), снапшот сохранён на диск (`POST /v1/snapshots`).
- [ ] **Шаг 3 (`15–20 golden queries`)**: прогнана таблица из 15–20 контрольных запросов магазина во вкладке `/admin` → **Проверка поиска (Live + X-Ray)**.
- [ ] **Шаг 4 (`docker stop` fallback)**: выполните `docker stop eidos-search`, введите запрос в поиск на витрине магазина → магазин обязан без ошибки 500 отдать штатную выдачу CMS, после чего запустите `docker start eidos-search`.

## 4. Таблица приёмки 15–20 Golden Queries (шаблон PASS / FAIL)

|---|-------------|----------------|---------------------------|------------|--------------------|
| 1 | Категория + назначение | `недорогие наушники для бега` | Только категория «Наушники», без кроссовок (`Category Gate: hard`) | Наушники и аудио | PASS |

## 5. Регламент 14 дней и критерий Go / No-Go

- **День 1**: Поднятие self-hosted Docker, настройка `ADMIN_KEY` / `SEARCH_KEY`, первичная выгрузка прайса и фиксация снапшота.
- **Дни 2–3**: Прогон 15–20 Golden Queries, проверка `docker stop` fallback на тестовом или боевом контуре.
- **Дни 4–12**: Мониторинг вкладки **«Журнал запросов»** (`Только пустые (0)`) в `/admin`, добавление 5–10 синонимов и разговорных сокращений покупателей в **«Словари и синонимы»**.
- **День 14 (Go / No-Go)**:
  1. **≥ 80% запросов** из Golden-таблицы имеют статус **PASS** (точный Top-3 без чужих категорий).
  2. **100% мусорных запросов** возвращают честный `0` (`count: 0`).
  3. **CMS Fallback** при остановке контейнера отрабатывает без ошибок на витрине.
  4. Снижение доли пустых выдач (`Zero-Result Rate`) за счёт словаря синонимов.
